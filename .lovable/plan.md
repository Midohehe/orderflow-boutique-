# خطة: قسم "تأكيد الطلبات" الاحترافي

## الهدف
نقل كل أدوات تأكيد الطلبات من صفحة الطلبيات إلى **تبويب/صفحة مستقلة** اسمها "تأكيد الطلبات"، وإضافة كل الخصائص اللازمة لمركز تأكيد احترافي يستخدمه موظف خدمة العملاء يومياً.

---

## 1) التنقّل والمسار
- إضافة عنصر جديد في الـ Sidebar تحت قسم "الطلبيات":
  - **تأكيد الطلبات** → `/dashboard/confirmation` (أيقونة `PhoneCall` أو `ShieldCheck`)
- إزالة أزرار/فلاتر التأكيد (مؤكد / لم يرد / تأجيل / إلغاء / اتصال / واتساب) من صفحة `/dashboard/orders` تبويب "قيد الانتظار" — تبقى فقط حالة التأكيد كـ Badge للعرض.
- إضافة شريط أعلى صفحة الطلبيات: "اذهب إلى مركز تأكيد الطلبات →".

## 2) واجهة صفحة "تأكيد الطلبات"

### رأس الصفحة — بطاقات إحصائية حية
- بانتظار التأكيد / مؤكد / لم يرد / مؤجل / ألغى
- **نسبة التأكيد** (مؤكد ÷ المُعالَج)، **متوسط عدد المحاولات**، **عدد طلبات اليوم**
- شريط تقدّم: "تم تأكيد X من Y اليوم"

### تبويبات داخلية
1. **بانتظار التأكيد** (افتراضي)
2. **لم يرد** — مع عدّاد المحاولات
3. **مؤجل (Callbacks)** — مرتبة حسب `postponed_until`، وتنبيه أحمر للمواعيد المتأخرة، وقسم "اليوم".
4. **مؤكد** — للمراجعة
5. **ألغى أثناء التأكيد**
6. **سجل المحاولات (Activity log)** — كل العمليات بترتيب زمني.

### فلاتر وبحث
- بحث برقم الهاتف / الاسم / كود الطلب
- فلتر حسب المنتج، المدينة، التاريخ (من/إلى)، الموظف المُسنَد إليه
- ترتيب: الأقدم أولاً (افتراضي) / الأحدث / حسب موعد إعادة الاتصال
- ✅ كشف **العملاء المتكررين** (نفس رقم الهاتف عنده طلبات سابقة) مع شارة.
- ✅ كشف **الطلبات المكررة** (نفس رقم/منتج في آخر 24س).

### قائمة الطلبات — صف مدمج جاهز للعمل السريع
لكل طلب:
- اسم العميل + رقم الهاتف (قابل للنقر للاتصال)
- المنتج والمتغيرات والكمية والسعر
- المدينة/المنطقة + العنوان
- عمر الطلب (منذ كم ساعة) + عدد المحاولات
- آخر ملاحظة تأكيد
- شارات: عميل متكرر / مكرر / مشكلة شحن

أزرار الإجراءات السريعة:
- 📞 **اتصال** (tel:) — يزيد عداد المحاولات تلقائياً
- 💬 **واتساب** مع اختيار **قالب رسالة** قابل للتخصيص
- ✅ **مؤكد**
- ❌ **لم يرد**
- 📅 **تأجيل** (مع اختيار تاريخ/ساعة)
- 🚫 **إلغاء** (مع سبب من قائمة جاهزة + مفتوح)
- 👁 **تفاصيل** (يفتح OrderDetailsDialog الموجود)

### لوحة جانبية (Drawer) عند فتح طلب
- بيانات العميل الكاملة + تعديل سريع للعنوان/المدينة
- **سجل المحاولات السابقة** لهذا الطلب (تاريخ، نتيجة، ملاحظة، الموظف)
- **سجل طلبات العميل السابقة** (نفس الرقم) — مفيد لمعرفة سلوكه
- خانة ملاحظة سريعة + اختصارات لوحة المفاتيح:
  - `C` مؤكد · `N` لم يرد · `P` تأجيل · `X` إلغاء · `W` واتساب · `→` التالي

## 3) إعدادات مركز التأكيد (صفحة فرعية `/dashboard/confirmation/settings`)
- **قوالب رسائل واتساب** متعددة (تأكيد أولي، تذكير، تأجيل، عرض خصم)، مع متغيّرات: `{اسم}`, `{منتج}`, `{سعر}`, `{مدينة}`.
- **أسباب الإلغاء** الجاهزة (قائمة قابلة للإضافة/الحذف).
- **سياسة المحاولات**: عدد المحاولات قبل النقل التلقائي إلى "ألغى" (مثلاً 3 محاولات "لم يرد" خلال 48 ساعة).
- **ساعات العمل** + تحذير عند الاتصال خارج الدوام.
- **تذكيرات تلقائية**: إشعار داخل التطبيق عند حلول موعد إعادة اتصال.
- **توزيع تلقائي**: إسناد الطلبات الجديدة على الموظفين الفرعيين بالتدوير (Round-robin) أو يدوياً.

## 4) قاعدة البيانات — إضافات

```text
orders:
  + assigned_to             uuid (موظف التأكيد المُسنَد)
  + last_attempt_at         timestamptz
  + cancellation_reason     text  (سبب الإلغاء من التأكيد)

confirmation_templates (جديد):
  id, owner_id, name, channel ('whatsapp'|'sms'), body, is_default

cancellation_reasons (جديد):
  id, owner_id, label, sort_order

confirmation_settings (جديد، صف واحد لكل owner):
  owner_id, max_no_answer_attempts, auto_cancel_after_hours,
  work_hours_start, work_hours_end, auto_assign_enabled
```

كل الجداول الجديدة بـ RLS:
- قراءة/كتابة لصاحب المتجر وأعضائه (`is_member_of(owner_id)`).
- `set_owner_id` trigger كالباقي.

`order_confirmation_attempts` الموجود سيُستخدم كما هو لسجل المحاولات.
